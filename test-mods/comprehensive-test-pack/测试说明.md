# 桃源综合测试数据包：人工测试说明

这是一份给 PC 端测试人员使用的游戏内说明。本包现在是**纯数据包**：它只提供命名空间下的内容定义，不修改游戏源码，不包含开局注入、金钱修改、UI 修改或怪物血条修改。

## 一、测试前准备

1. 仅在 PC 版 Web/Electron 环境测试。
2. 在主菜单打开“数据包预检”，选择本模组目录，或选择随附的 `comprehensive-test-pack.zip`。
3. 等待导入、安装和启动交接完成，确认“桃源综合测试模组”通过预检并显示为已启用。
4. 导入后可以创建新游戏验证原版流程。**不要期待开局金钱、背包、武器或料理列表发生变化。**

## 二、包内定义的游戏内容

这些条目是数据包中实际存在的内容定义，数量和数值以游戏当前加载结果为准：

| 内容 | 定义 |
| --- | --- |
| 种子与作物 | 测试萝卜、番茄、甜瓜、豆荚、薄荷；成熟天数分别为 2、3、4、3、2 天，番茄和豆荚支持再生长，甜瓜声明支持巨型作物。 |
| 食物与材料 | 测试浓汤、田园沙拉、香辣串、甜瓜派，以及测试纤维、香料、野菇等材料。 |
| 武器 | 余烬长刃、侦察短刃、训练重锤，分别是剑、匕首、棍棒，并声明各自的攻击力、暴击率和商店材料。 |
| 穿戴装备 | 测试戒指、测试帽子、测试鞋子，分别声明暴击、防御和移动速度效果及制作材料。 |
| 附魔 | 余烬、血契、幸运符、坚握，包含攻击、暴击、吸血、幸运和防御等数据效果。 |
| 怪物与掉落 | 训练史莱姆和训练掉落表，用于验证怪物及掉落定义的格式和引用关系。它没有自动加入普通矿洞怪物池。 |
| 标签 | 测试种子、测试食材两个标签，用于验证标签引用和配方数据。 |

配方定义包含四道测试料理及其材料、恢复值和 buff 数据，但当前纯数据包没有自动解锁料理的入口；因此新游戏中不保证看见或制作这些料理。

## 三、导入和原版流程测试

1. 分别使用目录和 ZIP 导入，确认两种来源都能完成预检，不出现 `Archive entry paths must be non-empty normalized POSIX paths`。
2. 确认包的名称、版本和 PC 端数据内容入口显示正常。
3. 导入包后创建新游戏，确认原版初始金钱、青菜种子、木棍和原版玩法入口保持不变。
4. 进入农场、设置和存档界面，确认导入包不会破坏原版启动、存档读写和退出流程。
5. 退出并重新启动，确认包的启用状态和存档状态按照当前数据包管理流程保持一致。
6. 禁用包后重新启动，确认原版仍可进入；不要把第三方条目自动从背包或旧存档中清除作为验收条件。

## 四、数据定义验收

如果当前版本提供可查看注册表或内容预检明细，逐项检查第二节列出的条目：

1. 每个条目 ID 使用 `taoyuan_test_suite:` 命名空间。
2. 作物的种子引用、季节、成熟天数、再生长和巨型作物字段符合表格描述。
3. 食谱的材料、产物、恢复值和 buff 字段完整，材料引用都指向本包物品或标签。
4. 武器、穿戴装备和附魔字段完整，装备引用的附魔与材料均存在。
5. 训练史莱姆的掉落表引用存在，掉落物数量范围和概率可被正常读取。

若游戏当前没有把这些第三方注册表直接展示到玩家界面，应记录为“内容已导入但无现有玩家入口”，不要把它误判为数据包 ZIP 导入失败。

## 五、预期结果

- 目录和 ZIP 均能成功导入，且 ZIP 内条目路径可被正常读取。
- 数据包 manifest 不含 gameplay modifier；导入不会改变开局金钱、开局物品、初始武器、料理解锁或怪物血条颜色。
- 包内八类数据入口均能通过预检，内容 ID、字段格式和引用关系有效。
- 新游戏和原版存档流程不受该包影响。
- 训练史莱姆不会因为仅注册了怪物数据就自动出现在普通矿洞中。

## 六、发现问题时请记录

- Web 还是 Electron、游戏版本和操作系统。
- 使用目录还是 ZIP，以及导入前后的预检摘要和错误文本。
- 包启用状态、存档槽位、当前日期/季节/天数。
- 预检明细中缺失的 registry、content ID 或字段路径。
- 复现步骤、实际结果、预期结果，以及截图或错误日志。

## 七、当前明确忽略的功能

- 无限金钱和新游戏初始金钱修改。
- 自动发放固定或随机种子、材料、武器和附魔。
- 自动解锁四道测试料理。
- 修改怪物血条颜色。
- 自动把训练史莱姆加入普通矿洞。
- 只靠数据包把自定义条目接入所有既有 UI、背包、商店、战斗和存档玩法入口。

这些能力需要游戏源码中的运行时或产品入口支持，本轮按用户要求不保留临时代码实现。
